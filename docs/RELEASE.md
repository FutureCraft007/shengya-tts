# Android 0.7.2 Kokoro 生成回调修复

日期：2026-10-28。

修复 Kokoro 原生库要求 `invoke(float[]):Integer`，而 Kotlin invokedynamic 回调仅提供 `invoke(Object):Object` 的兼容问题。原生调用会留下方法查找异常，后续 JNI 操作可能终止应用。改为具名、保留签名的回调类，并在调用前检查签名；继续支持取消。新增方法签名、反射调用与取消回归测试，以及最终 APK 的 DEX 方法签名校验。

Android 版本代码升至 11，应用 ID、签名、模型目录和历史数据不变，已下载模型无需重装。Windows 沿用 0.7.1，不受此 Android JNI 回调影响。

已在旧回调上复现方法查找失败；用户手机尚未获取崩溃栈，也未完成 vivo 实机回归，不能仅凭此测试排除其他设备问题。

- Android 的应用 ID、Java/JNI 包名、数据库、模型文件名、Keystore 名称、连接口令偏好和 loopback 协议标识保留。品牌文案、Gradle 工程名和发行文件名改变，版本为 0.5.0/code8。
- Android 继续提供原有 Base/CustomVoice、逐字稿完整克隆、云端采样、本机降噪、历史和手动启用的六路 API。
- Windows 基于 Volcano Voice Studio 的桌面实现，提供独立 EXE、本地模型下载/导入、Base/CustomVoice、WAV 完整克隆、云端采样、历史和导出。双端功能见根目录功能表。
- Windows 数据采用新的 `ShengyaTTS` 用户目录，不读取或迁移其他客户端的凭据及录音。
- 这是公开发布前的本地候选版本。本次未创建远程仓库、推送 Git 历史或上传发行包。

## 来源和发布准备

保留上游 MIT、RNNoise BSD、运行时及模型独立许可。安卓既有适配的来源说明保留；维护者应确认其自有移植部分的公开授权。本次未将历史来源改写为“全新独立实现”。

源码包通过显式范围选择，排除构建目录、日志、缓存、签名材料、个人配置、模型、录音和旧 Git 数据。`SOURCE-MANIFEST.json` 记录入包文件摘要。RNNoise 已知模型是软件运行资源，单独核对固定 SHA-256。

正式公开二进制应采用维护者自己的 Android 发布密钥与 Windows 签名流程；本机试用 APK 延续现有测试签名，Windows 包未代码签名。不要提交本地签名文件。

真实模型推理、音质和目标电脑兼容必须与程序构建、单元测试、界面测试、原生 CLI 启动分别记录；未测试的项目不视为已验收。Android 六路实际手机表现仍需实机确认。
